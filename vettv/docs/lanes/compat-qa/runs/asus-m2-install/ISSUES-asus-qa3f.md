# Asus GL552VW real-hardware issues, qa3f g51fd948 (2026-10-27 CT)
Install verified on sda (EDILOCA EN206 476 GiB). Boots to the desktop, clock is correct (CT).

- R-T05a [IDs pinned 2026-10-27 from pci-ids-qa3f.txt: ME 8086:A13A, Serial IO 8086:A161 (A160 is not in the dump), card reader 10EC:5287, plus PCH/host-bridge parts. 3g 10337654ef NO_DRV: 8086:1903/1911/A121/A123/A131/A13A/A161; 8168/5287/095A/139B/A12F/A170 deliberately left for real drivers, A12A left out (class unknown); SuppressNewHWUI covers the rest. GPU 10DE:139B (GTX 960M) runs on the fallback display driver.]: New Hardware Wizard for several "Other PCI Device" entries and a "Communication device" (likely ME/HECI 8086:A13A). Fix plan: 3g sets SuppressNewHWUI in the image, plus NO_DRV for the pinned IDs. Need VEN/DEV from Vet.
- R-T05b: The touchpad is dead. It's likely ELAN I2C HID behind Serial IO I2C (A160/A161), and ReactOS has no driver for either. Known gap.
- R-T05c [confirmed xHCI 8086:A12F. BIOS Legacy USB Support was already on and the USB mouse still fails, so the gap is xHCI only; M-level]: Wizard for a "USB controller". Likely xHCI 8086:A12F, and our tree has no xHCI driver, so a USB mouse won't work either. Workaround: the BIOS "USB Legacy Support" option, which needs Vet's OK. A real xHCI driver is M-level work.
- R-T05d: Wizards for "High Definition Audio Device" and "Intel Audio DSP". Likely Skylake HDA/SST (8086:A170 and its codec). No sound, hdaudbus binds A170, but there is no HDA codec driver in the tree, which is M-level work (per Build).
- R-T05e: CLOSED. Vet confirmed the launcher did auto-start on the Asus and he closed it himself during the driver popups. Boot-to-launcher works on real hardware.
- R-T05f [confirmed 10EC:8168 RTL8168; no driver upstream either; long term: port BSD re(4), or a user-supplied Realtek driver, never bundled]: The Ethernet controller has no driver. It's likely Realtek RTL8111/8168 (10EC:8168). The tree has rtl8139 only, no RTL8111/8168 driver (per Build), and Build is checking upstream for one. No wired network until then.
- R-T05g [confirmed Intel 7265 8086:095A; out of scope]: The Wi-Fi network controller has no driver. On the GL552VW it's likely Intel AC 7265/3165 (or a Qualcomm/Realtek part). ReactOS has no driver for any of these. Known gap; workaround is a USB NIC (but there's no xHCI, see R-T05c) or wired Ethernet once R-T05f is fixed.
- R-T05h [3g da159b8de7: NO_DRV ACPI\PNP0C09 and ACPI\ACPI_PWR] (from Lead's video): wizards for ACPI Power Resource (about 6), the ACPI Embedded Controller, several "Other ACPI device" entries, and an "Other memory controller". Pressing Enter on one gave "driver could not be found" and did no harm. These go in the 3g Suppress/NO_DRV set.

Rules (Lead, 2026-10-27): 3g covers only a quiet first boot (SuppressNewHWUI plus NO_DRV entries). xHCI (R-T05c), the HDA codec (R-T05d) and RTL8111 (R-T05f) are M-level work tracked in the risk register. On the Asus, mark sound checks "N/A (R-T05d)", not FAIL. Keep judging sound in the VMs.

- R-T05i (new): The image hive has stale QEMU PCI Enum keys (1022:2000, 1234:1111, 8086:1237/2415/7000/7010/7020/7111/7113). Harmless so far; Build is deciding whether to clean them out of the shipped image. QA will check that 3g on the Asus lists only real devices.
